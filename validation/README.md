# 验证范围 · v0.1.0

本机实测环境：macOS 27.2、SketchUp 26.0.428、Blender 4.5.12、Python 3.12、官方 MCP Python SDK 2.3.0。记录以 2026-11-01 本地验收为准；Linux CI 仅运行核心/协议测试，其他 SketchUp/Blender 版本和 Windows 未验证。

|---|---|
| 核心与协议 | 27 项自动测试，包括真实 stdio 握手、语义冲突、分版分范围阶段门、过期证据、真实网格/面环检查；不能代替原生软件验收 |
| 从零五阶段 | `e2e/r08–r10` 三个最终代码干净任务轮次：两候选 → 固定选案输入 → 原生围合/楼板/洞口/楼梯 → 精修门窗/防护/灯具/资产 → 实际保存关闭重开、实际贴图导出、检查、三视图人工审看及冻结交接。固定任务卡不是自由方案设计质量的普遍证明 |
| 接续手改 | `recovery/r04–r06` 最终代码三轮：保全模拟原生手改、拒绝旧修订、范围违规回滚、组合/撤销、三实体并集、开洞补洞、同 ID 恢复、真实关闭重开 |

可重跑脚本为 `scripts/validate_native.py`、`validate_recovery.py`、`validate_asset.py`、`validate_workflow.py`。五阶段脚本分准备和交接两步：先看实际截图并写出明确显示核查报告，再 `--finish`；不能预填“已看图”。三轮详细记录及模型随 Release 案例包提供。

## 已发现并修复的失败

- Blender 沙盒 Metal 启动失败单独记录为环境问题；默认工厂 Cube 污染、DAE XML 参数冲突属于实现缺陷，修复后重跑。
- 早期把激活已有窗口误记为文件重读的 native r02–r04 已作废；后续轮次使用真实关闭/打开事件及新文档 ID。
- 原生面枚举顺序、浮点负零引起比较误报，采用规范化面环比较，保留几何方向与应用 UV。正总容积掩盖反向壳体的旧缺陷已增加回归。
- 场景选择时关闭过渡并显式恢复保存的相机；保存于组编辑中的文件即使已写磁盘，也不能记为冻结完成。

## 明确保留的未查范围

水平通行只覆盖声明路线、宽高、端点与转角包络；踏步检查是起点、每级及到达面的支承/竖向净空采样，不认证连续步态。门/家具动作仅检查声明刚性状态，中间动作未查。防护检查限声明实心直边；荷载、锚固、竖杆间隙及法规适用性另查。旧对象未声明闭实体时标未查，不因体积或哈希而通过。

Plan E 的采光、支承、隔声防火、机电排水、五金和结构未决项完整保留在案例 context 中。底稿 reader 不做最终消隐、线型或标注。三轮固定任务通过不表示可无人判断地完成任意建筑任务。

追加检查中 `e2e/r04` 在原生关闭/重开通知中发生 SketchUp 进程崩溃，保留为失败，不能恢复为完成。其异常与此前工具栏崩溃不同；无证据归因于内存耗尽。后续测试应独占软件实例，核对实际进程及桥 SHA；其他聊天或插件测试不能共用当前活动文档。`r05` 因连接了旧桥的另一进程而不计最终代码验收。

最终发布前复跑使用用户确认关闭全部软件后的单实例环境。open 激活竞态已以精确目标等待修复，reopen 将关闭和打开分置不同事件循环；加载代码与服务 SHA 不匹配会阻止写入。失败记录未替换成通过。
