# 工具、文件与故障处理

## 工具职责

以用户当前编辑软件为中心，不为了套用流程强制迁移。

- 原生建筑工具负责建筑尺寸、空间、可编辑构件和正式基线。
- 参数生成器负责适合规则化的部分；手工深化后的模型不能默认由旧参数重建。
- 表现软件接收同版几何，负责材质、灯光和镜头。
- 实时查看器按需要承担连续空间体验和选镜头；不因已存在 Unity 工程就要求每次建模都经过 Unity。
- 制图工具负责专业图面表达；图上的几何修正要登记为建筑变更或明确的表达简化。
- 打印工具接收独立制造副本；制造加厚和缩尺不得回流污染建筑模型。

优先使用已经可用的原生接口/连接器/CLI，UI用于用户实际编辑体验、显示检查及接口缺失的操作。使用具体软件前加载适用操作技能并核对实际能力。此技能没有内置 SketchUp、Rhino、Blender、Unity 或 Figma 适配器，也不预设当前机器的软件版本。

## 文件组织建议

```text
项目/
  工作模型/            用户连续编辑的权威模型
  工作流/R01/          manifest.json、简报、本轮记录、核查
  工作流/R02/          后续模型版本的新基线
  发布/修订号/         模型与交接入口，必要时存不可变副本
  派生/图纸|渲染|漫游|打印/
  内部回退/            不作为默认展示文件
```

这是参考布局，沿用用户已有目录即可。探索版可以独立文件或同文件方案；精修阶段优先一个当前文档加内部回退。文件名和修改时间不足以证明最新，入口、内容和指纹共同确认。

## 文件基线工具

`model_baseline.py init` 建立某一模型修订的登记，不复制或修改源模型。记录源文件的绝对路径和SHA，复制可填写模板。

`register` 登记一个输出及其依赖；默认依赖 `source`，也可重复 `--depends` 登记几何数据、镜头或图纸底稿。可用的输出类别是 `data/report/drawing/render/walk/print/preview/other`。本工具不能从报告内容推断其真实性，也不能自动发现未登记的隐式依赖。

```bash
python3 /absolute/skill/scripts/model_baseline.py register --manifest /work/R01/manifest.json --id geometry --file /work/geometry.json --kind data --depends source
python3 /absolute/skill/scripts/model_baseline.py register --manifest /work/R01/manifest.json --id render-start --file /work/model.blend --kind render --depends geometry --note 同版几何转接，尚未完成效果图
```

`check` 重算文件指纹并逐层检查登记的依赖。路径缺失、输出被改或上游失效均返回退出码2；格式/命令错误返回1；文件链一致返回0，但总是提示设计与几何仍需外部核查。一个ID不能重复登记覆盖，避免冲掉旧证据。更新源模型或派生成果时使用新轮次基线，重新核查后登记。

文件链工具无法判断打开文档的未保存状态，也不是实时监控；需在接管、发布或发现版本疑问时调用。

## 把历史脚本变成可复用工具前

本轮以文档固化流程时，不必改写全部历史脚本。需要真正复用某算法时，再逐项完成：

1. 检查脚本是读取、生成、替换还是定向修补；有哪些绝对路径、临时环境、旧实体ID及固定几何假设。
2. 将输入、输出、单位、基线指纹和作用范围显式参数化。已有人工修改时避免覆盖输出。
3. 先在独立样件执行；验证原生几何、保存重读和副作用。重复运行是否幂等必须实测；不幂等则以基线校验和拒绝重放保护。
4. 报告绑定本次源模型、脚本版本和结果；未知结果先检查回执/输出，不直接重发写操作。
5. 临时环境失效时依据明确依赖重建；不将某次 Metal 初始化失败、UI弹窗或权限阻止误判为模型损坏。

## 常见中断的处理

### 有依赖的任务按顺序完成

读取基线 → 生成候选 → 原生写入成功 → 保存重读 → 核查实际几何 → 更新场景并保存 → 复读几何/显示 → 绑定证据 → 发布。每步确认进程退出码及对应输出后，才能启动依赖它的下一步。不得在生成器仍写文件时启动导出、核查或渲染；不同版本可独立处理，但必须各自完成前置步骤。

长任务保留进程ID和日志；轮询同一任务，不因暂时无输出重复启动。先做低成本的指纹、对象、几何检查，再做昂贵的渲染；同版检查未失效且无新疑点时直接复用。循环中缓存不变的顶点数组、网格和空间候选，避免每个三角面重复创建全对象数组。

复杂布尔样件失败先缩小到具体构件。圆管转角可保留可编辑的分段管件和连接件；这只在实体有效、节点连接及原生编辑通过时成立。有意嵌入需限定具体对象对及实际连接范围，不用整组豁免隐藏失败。

临时虚拟环境只是本机运行条件，不能作为可移植交付依赖。记录解释器/库版本、历史辅助脚本路径及适用输入；需要重建环境时先检查依赖，再在副本中验证。生成器有写操作且绑定旧基线时，交接明确标为不可直接重放。

调用历史工具前做一次轻量预检：解释器及必要库可导入、输入文件与预期指纹一致、输出未指向用户当前文件、原生应用启动参数包含目标文档。启动命令成功只代表已发出请求；仍须核对当前文档和脚本回执。返回进程ID时继续等待同一进程的退出状态；不能因预计写入很快就启动读取它的应用或导出器。

原生写入若有量化网格，设计比较基准先按实际写入规则归一化，并保留原设计、量化规则和误差记录。区分坐标量化、实体变形与采样容差；不得通过放宽碰撞/净高阈值消除精度失败。长构件的小坐标舍入可能累积为体积误差，先核对写入数据再决定修复。

| 现象 | 下一步 |
|---|---|
| 当前文件与基线哈希不一致 | 先读取差异和最近用户修改；把新状态作为下一轮基线，不能修改旧哈希掩盖变化 |
| 窗口显示旧模型，磁盘已更新 | 核对未保存内容和此前授权；允许时刷新当前窗口，避免重复开许多标签；有未保存手改先保全 |
| 操作超时或结果未知 | 读取同一次操作的回执/输出/当前实体状态，确认后再决定重试 |
| 布尔计算失败 | 缩小到失败对象，检查闭合、法线、容差和坐标；报告未检项，不能跳过后仍写全量通过 |
| 原生工具无法推拉 | 检查实体面环、共享边、平面方程和层级；不能只“炸开全部”或转成更细碎的网格 |
| 新增结构破坏空间 | 返回结构与空间联合设计，提供保留关键空间的选项；不要悄悄删除构件后声称结构仍合理 |
| 导出后缺墙/重影 | 检查父级隐藏、互斥表达、重复导入及变换；先确定显示语义，再补几何 |

普通任务不启动长期监控、不自动发布外部内容、不顺带重构工具。需要额外动作时按用户实际任务范围处理。
