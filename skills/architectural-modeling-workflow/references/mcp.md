# MCP 执行与恢复

服务通过 stdio 运行；一次服务绑定一个工作目录。先 get_capabilities、project_get（新项目用 project_init）、sketchup_state，核对活动文档、未保存状态、版本及单位。

已有 JSON 事实底表用 project_link_authority 指向单一权威来源，不能同时维护第二套区域/关系表。外部底表改变后先查用户手改、核对变化，再刷新链接；刷新指纹本身不是设计或几何验证。

阶段状态与文件检查分开。精修和交接前，按模型版本声明本项目必须覆盖的检查范围；阶段检查按每版每项核对，不能由一份局部报告代替全部要求。decision_record 只记录真实用户决定及可追溯来源；stage_check 列缺口，stage_advance 只推进一个阶段，stage_reopen 返回受影响阶段。已有项目可带实际交接依据从适合阶段进入。

## 原生写入

SketchUp 本地 Ruby 扩展在原生事件循环处理文件队列。所有写入传 expected_revision 和唯一 operation_id；版本冲突先读现状，不回退手改。相同 ID 与相同参数可查询/恢复；超时后先 native_job_status 查询同一次操作。replayed 回执里的 state 是原操作时点，后续写入前重新读取当前状态。unknown 不等于失败，禁止换新 ID 重复写。运行中原生事务不能半途取消；排队任务可取消，失败事务回滚，保留写前文档副本。

用明确参数的 create、opening、transform、material 等常用工具。开洞按宿主选择，不合并全部避让体。特殊造型可使用可信工作区 Ruby 脚本，仍需目标范围、当前修订、操作 ID 和最终保存重读。脚本执行拥有原生进程权限，范围比较不是代码安全沙盒。

创建/修改 → 原生查询 → 临时编辑与撤销 → 场景等写回 → save → reopen → export → checks_run → 目视显示 → evidence_register。指纹冻结之后再写模型会使对应证据失效。原生网格封闭不保证组内选面/推拉体验，必须抽查。

## Blender 资产

asset_build 在独立进程、新输出文件中制作或续改。source 使用用户当前 .blend 并携带其 SHA；输出不可覆盖源。保留部件/修改器/材质，记录尺寸、朝向、原点、安装基准及许可。asset_job_status 确认进程退出成功及新进程重读；取消的输出无效。导入 SU 后另查尺度、实例变换、材质、编辑和动作关系。

## 证据边界

checks_run 读取保存后的真实几何，核查拓扑、实际实体碰撞、楼板面环/板厚、明确路线的身体空间与脚下承托，以及范围外差异。层级通行、门扇状态、每级踏步、支承和防护须按项目列完整检查范围。工具不能自动推断所有房间用途或任意生活动作。

证据分别记录设计确认、几何、保存重读、原生交互和显示。新查、凭真实范围外比较继承、失败与未查分别登记。evidence_inherit 仅能继承语义基础及完整依赖未变的真实原报告；同一模型哈希不能把局部检查升级为全屋认证。handoff_export 在阶段条件通过后冻结独立交接包。

连接后核对软件进程、加载桥 SHA 与服务随包代码；不匹配时保全当前模型，安装并重启匹配的扩展。macOS 打开文件的返回值不证明目标已经成为活动文档；重读须另有关闭/打开事件和新文档身份。多个聊天不得同时操作同一活动文档，独占的验收工作区也须核对实际进程。

原生几何导出同时携带实际贴图 PNG、相对路径和 SHA；原始像素、材质色与透明度分别记录。最终交接逐一复制并核对纹理，不能只交材料名。

## 反馈与 API 参考

截图返回路径等结构化回执及可查看的 MCP ImageContent；必须实际查看图像。工具注解仅描述行为，不代替权限与事务。任意 Ruby/Python 脚本不是安全沙盒。按需查 [API 索引](api/index.md)，优先在已有事务中组织相关修改，不把有验证依赖的调用合并。空间证据继承会比较全部导出环境（包含新增对象）；远处变化也可能要求重查，原范围不扩大。

不同模型文件的继承还需项目当前记录及修订历史证明同一唯一模型标签；未知或跨版本分支不继承。旧拓扑报告兼容读取，未知几何报告保守按空间检查处理。
