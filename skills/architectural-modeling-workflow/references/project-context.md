# 跨对话共享项目事实

用于已有项目接管、编号与功能核对、用户纠错后的连续修改。目的在于让下一次对话读到同一组有效决定，不靠检索全部历史聊天。

## 固定入口和单一维护源

在项目根目录的既有入口维护短链接；使用支持项目指令的环境时，在项目级`AGENTS.md`指向该入口。沿用已有文件名和格式，不强制建立新目录。

项目资料至少回答：

- 当前可编辑文件、修订、最近保存指纹、应用窗口是否已核对；源模型与生成器历史输入分开。
- 每个稳定区域ID对应的功能、室内/室外/灰空间、主体完成面标高及零点换算、可达或不上人要求。
- 通行连接的起终点、类型及中间平台；视线联系另记。两条链、两个系统和单条梯跑不能混称。
- 实体路径或稳定ID及其所属模型版本；软件重建ID时保留映射。
- 决策状态、来源、适用版本、被何条决定替代；待实现的决定与已保存的结果分开。

只有一份可手工维护的当前表。确需机器读取时可用JSON/YAML为底表并生成可读页面；否则维护一份Markdown表即可。不要让两份独立编辑的完整表竞争权威。日志存过程，当前表存有效值，历史文件顶部标明适用版本及当前入口。

跨项目的新对话不一定能自动发现该目录；记忆或索引只存项目路径与入口，进入项目后读取实时底表，不在记忆里复制容易过期的区域表。

## 修改前的语义核对

1. 从用户最新指令解析受影响区域，以ID读取整行信息和相关连接；屏幕“左/右”需结合相机换算为模型轴向后记录。
2. 对涉及的楼梯或通道写出起点ID/功能/标高、终点ID/功能/标高、经过区域及室内外属性。ID连续不代表楼层或路线连续；同标高也不等于已连通。
3. 与实际模型的对应面、完成面、墙门和场景核对。功能名与空间位置匹配后再生成；不能只核对文字标签。
4. 如当前指令明确修改旧决定，直接采用新决定并登记替代关系；不重新要求已给出的许可。如出现会改变方案的指代歧义，先查现有证据，仅对剩余关键歧义询问。

探索可以只做简化几何，但区域身份和已定连接不可省略。语义冲突仅阻塞依赖它的建模，独立的只读核查可继续。

## 更新和冲突处理

用户明确决定是意图来源；当前应用状态和保存模型是几何来源；两者冲突是待协调事项，不能由一方无声覆盖另一方。旧脚本默认值、旧报告和旧版本只用于解释历史。

用户纠错后，更新当前行，标出旧决定已被替代，并清理仍作为当前输入使用的过期备注。不要只在最后追加一句，留下“床不移动”和“床已平移”两条同时有效。保留历史备份，不能为了文件链通过而篡改旧报告。

几何保存并重读后才更新模型指纹、实体定位和派生数据绑定。单纯整理工作流时不要改模型；记录是否只验证了磁盘而没有检查当前窗口。底表校验能发现缺ID、错误引用或标高不一致，不能证明功能合理、路径可行或窗口无未保存工作。

结束前做一次接手检验：只读固定入口，能否选对工作文件、解释本轮区域功能、复述两端连接、识别被拒绝的旧做法？若仍须依赖当前聊天，补齐缺失的最小信息。
