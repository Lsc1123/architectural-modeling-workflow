# 日常修改与阶段协作

日常顺序：读取现状与范围 → 修改 → 本体及邻接核查 → 完成必要写回 → 保存重读与显示核对 → 更新事实并简短交付。普通修复沿用阶段和已有授权；真实阶段变化才调用阶段迁移，明确交接才生成完整包。

通用要求唯一正文：[硬规则](../skills/architectural-modeling-workflow/references/hard-rules.md)。临时诊断图留在核查目录，沿用已有场景；MCP 流程无需另用独立脚本重复登记文件。

接管贯穿五阶段：读权威事实、实际文件与窗口，保护手改，核对单位、坐标、标高和实体身份。已有项目从适当阶段进入，缺陷返回受影响环节，不重演已完成的用户决定。

| 阶段 | 交付与检查 | 用户决定 |
|---|---|---|
| 探索 exploration | 简报、约束、空间意图、少量实质不同候选；边界、联系、关键可行性与暂定项 | 探索方向 |
| 选案 selection | 选中模型、理由、必须保留的关系、调整范围和未决项 | 明确选择 |
| 推敲 development | 原生墙板、围合、洞口、交通及家具占位；联合看体量、视线、动作和接口 | 重大空间变化 |
| 精修 refinement | 门窗、栏杆、铺装、家具、灯具和收口；本体、邻接、范围外、编辑、重读与显示 | 影响设计的取舍 |
| 交接 handoff | 冻结 SKP、真实几何、索引、坐标标高、证据与未决项；复杂平面及关键剖面底稿读取 | 接受阶段成果 |

## 从零探索

“场地很窄，我想研究错层和内部空隙，先不精分房间。”

先核对边界及空间意图，区分视线与通行；比较少量不同的剖面关系。探索不提前制作五金，不把所有体量相交当作碰撞。选案后登记模型、理由和保持项，再落实交通、围合与使用。

## 接续手改

“我改了楼梯和卧室位置，沿用现在的模型，补完整门外平台。”

先读窗口并保全未保存内容，逐项对照底表与实际模型。旧参数不可直接重跑。限定宿主和依赖，联查板厚、面层、门槛、落脚、转向、防护与支承，再比较范围外几何及材质。版本冲突先重读，不还原旧版本。

## 资产往返

“用合适风格的桌椅完成精修，保留继续编辑能力。”

先做一组组合样件。下载资源登记来源及许可，在 Blender 新文件或当前 blend 副本中制作，保留部件、修改器与材质。记录米制尺寸、原点、朝向及安装基准。新进程重读后，SU 实际导入、摆放、编辑、撤销、保存重开，检查落地、拉椅与通道。有意连接和非设计碰撞分别记录。

## 阶段工具

`project_init` 建项目；已有底表用 `project_link_authority` 链接，不维护竞争语义表。`decision_record` 登记真实决定及来源，`stage_check` 返回缺口。`stage_advance` 前进一个阶段，`stage_reopen` 返回受影响阶段。工具核对记录和证据绑定，不替用户判断设计好坏。

报告包含方法、明确范围、结果和源文件哈希。设计、几何、保存重读、原生交互、显示分开。证据继承要求完整依赖、语义基础不变及真实几何/材质比较。未查路线、动作和专业状态保留明确记录。

模板位于技能 `assets/`。裁切、爆炸及图面简化交给后续出图流程；影响真实空间的修改返回建模。
